# 图片识别

机器人可以把微信群中实际读取到的图片传入当前模型，理解截图、照片、图表及图中文字，仍按角色卡的语气回复。示例模型 `deepseek-flash` 的图像输入方式见 [DeepSeek 官方说明](https://api-docs.deepseek.com/zh-cn/guides/vision/)。

## 使用方式

1. **先发图再提问**：发送普通图片，然后 `@小鲸鱼 这张图写了什么`。
2. **先问再补图**：`@小鲸鱼 帮我看下截图`，随后发送图片；短时间内会合并处理，晚一点补发也可承接尚未过期的看图请求。
3. **引用指定图片**：引用图片并明确 @ 提问，按被引用的消息定位，不随意选择其他成员最近发的图片。
4. **对比两张图**：连续发送两张图片，再 `@小鲸鱼 对比这两张图`。普通问题默认只取最近一张。

只发图片而没有请求看图时，默认安静。明确结束对话会取消等待补图；图片本身不授予任何操作权限。

## 配置

将以下字段配置在本机 `config.json` 的 `bot.vision` 中，修改后重启：

```json
"vision": {
  "enabled": true,
  "context_sec": 120,
  "max_images": 2,
  "max_source_bytes": 33554432,
  "max_pixels": 24000000
}
```

- 图片上下文按群和发图成员隔离，默认 120 秒。明确引用图片按引用的消息定位，不使用跨群缓存。
- 每轮硬上限两张；一般问题只取最近一张，有对比请求时才带多张。
- 单源文件最多 32 MiB，输入最多 2400 万像素。上传前转成最长边不超过 1600 像素的 JPEG，并移除图片元数据，单张编码结果不超过 2 MiB。
- 输入支持实际内容为 JPEG、PNG、GIF 或 WebP 的普通图片；GIF 只取第一帧。微信独立动画表情消息、视频和合并转发中的图片未接入。

## 本地读取与后台运行

读取使用微信已缓存到本机的媒体，传递消息所属分片，避免相同 local_id 在不同数据库分片中指向不同图片。多账号环境会先将数据库与 Hook 当前账号对齐。

程序不调用“下载原图”界面，不弹出微信窗口，也不点击群图片。若本机只有预览图或缩略图，识别精度受其限制；没有有效缓存、解密失败或文件异常时会提示补发，不凭占位文字猜图。

首次提取图片密钥可能明显慢于普通聊天，之后仍受缓存、图像处理和模型耗时影响。后台读取不等于保证锁屏、注销或无桌面服务可用。

## 数据与回复边界

图片会发送给配置的模型服务，带有私人信息的图片需先确认授权和服务商的数据处理政策。群图不会自动加入表情收藏。

内联像素仅用于当前模型请求，不把 base64 写进聊天历史或普通日志；本次读取产生的解密临时文件会清理。微信原有缓存、依赖库的密钥缓存与模型服务自身的保存策略分别由相应组件管理，不代表从所有位置删除了图片。

图中文字、链接、二维码和指令都当作不可信分析内容，不因此修改角色或获得本地操作能力；OCR 不会自动作为已确认个人事实写入长期记忆。看不清或缺图时应说明，不捏造文字、游戏信息或未读到的图片内容。

## 验证与排错

单元测试覆盖隔离、超时、图文顺序、引用、失败回退、真实像素编码、临时文件清理及账号保护，运行方式见 [本地测试](TESTING.md)。模型支持图像输入不等于微信图片读取已成功：应先确认日志“群图片已附入模型请求”，再判断模型返回。

若出现无法读取、读取了错误账号或响应过慢，按 [故障排查](TROUBLESHOOTING.md) 第 10～11 节逐步检查。提交 Issue 时不要附原始群图、私人标识、数据库或密钥缓存。
