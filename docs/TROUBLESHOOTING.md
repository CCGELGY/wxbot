# 故障排查

发生账号验证、登录限制或封禁提示时，先停止机器人，按官方途径处理；不要靠增加发送次数、换号或绕过限制来排错。相关边界见 [风险声明](RISKS.md)。

以下检查在项目目录的 PowerShell 执行。标明“发送测试”的命令会发送消息，其余查询命令不启动机器人回复。

## 先定位到哪一层

```powershell
Get-Content .\logs\bot-stderr.log -Encoding UTF8 -Tail 80
Get-Content .\logs\bot-stdout.log -Encoding UTF8 -Tail 40
```

直接运行 Python 时也检查终端输出或 `logs/api_bridge.log`。日志中的耗时只是当前请求的观测，不是固定性能承诺。

| 现象 | 优先排查 |
|---|---|
| 没有“已启动 / 监听群” | 配置、Key、依赖、微信登录或启动报错 |
| 有“监听群”，新 @ 没有对应触发记录 | 群 ID、登录账号、称呼、监听与冷却 |
| 有触发记录，没有模型回复 | API、工具调用、超时或角色选择跳过 |
| 有“生成回复”，群里没出现 | Hook、目标、客户端状态与发送确认 |
| 文字能发，图片没有 | 表情开关、图库、选择 / 冷却、搜索与图片发送 |
| 同一条发了多次 | 多个部署、多个监听实例或人工反复测试 |

## 1. 启动失败或依赖导入失败

```powershell
.\.venv\Scripts\python.exe --version
.\.venv\Scripts\python.exe -m pip show wechatauto-replica requests
```

确认使用项目 `.venv` 的 Python 3.10 x64，不是系统里的另一个环境。缺少依赖时重新运行 `install.ps1`，或用该解释器执行 `-m pip install -r requirements.txt`。

`config.json` 不存在时先复制模板；已有配置不要覆盖。用下面命令检查 JSON 语法：

```powershell
.\.venv\Scripts\python.exe -m json.tool .\config.json > $null
```

不要在 JSON 中加入注释或尾随逗号。若出现“同一配置的机器人已经运行”，先找到已有实例，而不是复制目录重复启动。

## 2. API Key 缺失、401、模型不可用或超时

- Key 缺失：运行 `set-api-key.ps1`，重新打开终端。桌面程序或旧终端可能保留旧环境变量；不要在 Issue 中粘贴 Key。
- 401 / 认证失败：检查 Key 是否有效、是否有多余空格及当前环境变量名是否和 `api.api_key_env` 一致。
- 模型不可用：检查 `api.model` 与该 API 账户可用模型是否一致，不要把产品展示名称直接当成 API 模型 ID。
- 429 / 额度问题：检查余额、并发与调用频率；暂停重试，按服务提供方说明处理。
- 连接或 TLS 错误：本项目 API 使用直连，不继承系统代理；媒体代理配置不能修复 API 连接。先确认本机能访问所配置的 API 地址。

下面命令会调用真实 API，可能消耗额度：

```powershell
.\.venv\Scripts\python.exe .\api_bridge.py --test-api
```

## 3. 查不到群、数据库打不开或新群不触发

```powershell
.\.venv\Scripts\python.exe .\api_bridge.py --list
```

确认列表顶部账号正确，目标群真实存在，并把其 `username` 填入 `groups[].name`。如果群不在会话列表，可在微信里手动打开目标群，等待一条正常新消息后再查询。

数据库读取失败时确认微信已经登录、使用 64 位环境、当前用户有权读取本机账号数据；不要为排错发布数据库密钥或整个账号目录。多个账号 / 微信实例可能造成读取和发送指向不同状态，先正常退出不需要的实例。

配置修改后需要重启。启动日志应显示目标群 ID；默认跳过启动前消息，必须在“监听就绪”后发送一条新消息验证。`groups[].aliases`、`bot.bot_aliases` 和 `bot.name_aliases` 也应对应实际称呼。

## 4. 只有 @ 回复，或者不该回复时插话

先用真正的微信 @ 发一条独立问题验证，再查看“对话对象判断”“冷却中”和触发类型日志。

- 公开问题和追问会经过对象判断，可能误判；@ 别人、引用别人或明确结束对话会被跳过。
- `bot.proactive.enabled=false` 会关闭主动参与，但不应阻止明确 @。
- 主动时段、概率、每小时 / 每日预算影响插话；不要把随机插话当作程序存活检查。
- 角色允许短句、反问和 `<SKIP>`。没有回复可能是角色选择，也可能是判断问题，需要日志区分。

若需报告问题，只提供少量去除身份信息的连续消息及对应日志；单独截取最后一句通常不足以判断对象。

## 5. 生成了回复，但文字 / 图片发不出

典型错误：`Hook accepted, database confirmation timed out; NOT retried`。

这表示接口接受请求，但程序没在确认时限内找到匹配的本地发送记录。它既不能证明消息成功，也不能保证绝未发出；**先查看微信和日志，不要立即连续重发**。

检查本机 Hook 端口及所属进程：

```powershell
Get-NetTCPConnection -LocalPort 30001 -State Listen |
    Select-Object LocalAddress, LocalPort, OwningProcess

Get-CimInstance Win32_Process -Filter "Name='Weixin.exe'" |
    Select-Object ProcessId, ParentProcessId, ExecutablePath, CommandLine
```

应仅监听 `::1`，端口所属进程应属于当前登录的微信实例。OCR、播放器等带 `--type` 的子进程通常正常，不能仅按进程数量判断多开；需要重点检查是否有多个无此参数的主实例。

处理顺序：

1. 停止机器人，查看微信有无账号限制或错误提示。
2. 从托盘正常退出多余 / 残留主实例，确保没有旧实例占用端口。关闭主窗口通常只是收起，不等于退出。
3. 核对微信为 4.1.10.27 x64，DLL 来源、位置和哈希与 [Hook 说明](HOOK_SETUP.md) 一致。
4. 只启动一个主实例并登录，再检查端口归属。
5. 运行一次文件传输助手测试，成功后再恢复监听。

以下命令**会向文件传输助手发送一条测试消息**：

```powershell
.\.venv\Scripts\python.exe .\api_bridge.py --send-test filehelper
```

需要看到 `is_success=True`、`verified=True`。若仍失败，保留错误片段继续定位，不要关闭 `verify_send` 掩盖失败，也不要把 Hook 端口改为公网地址。

上游健康接口的 `IsLogin=0` 字段没有可靠维护，不能单独作为离线证据；`hWeixin` 非零也只说明模块已加载，仍需登录和发送验证。

## 6. 回复或图片很慢

按日志拆开耗时：

- 轮询默认约 1 秒；连续消息合并或未完成语句等待可能增加延迟。
- 模型、网页工具和记忆查询各有处理时间。先看“模型回复耗时”，不要只凭群里显示时间判断网络慢。
- 多条短句默认间隔 2～5 秒，是 `bot.multi_delay` 的节奏配置。
- 发送会串行排队；一次约 8 秒的确认超时可能拖住后续文字 / 图片，先排查第 5 节。
- 网络表情需要搜索、下载、审核，且有队列有效期和超时；文字先发、图片稍后或最终跳过都可能发生。

明确延迟来源后再调整相应设置。减小节奏等待不等于修复发送故障；不要为了提速去掉发送确认或无限增大并发。

## 7. 不发表情、联网找图没有结果

检查 `bot.stickers.enabled`、`network_enabled`，本地路径和 `mapping.json` 是否存在。语义图库 ID / 描述由 `sticker_choices.py` 配置；只加一条关键词映射不代表模型能选到该图。

每 2～3 次回复只是选图机会，还受语境、冷却、小时额度、近期重复过滤约束。严肃话题可能不发。日志显示“排队”不代表已经发送；应继续看候选搜索、审核、发送与确认结果。

搜索无结果、图片过大、格式不支持、审核不匹配或下载超时都可能导致跳过。网络媒体确需代理时设置 `bot.stickers.image_proxy_url`，默认留空；不要把失败候选强行当作合格图片发送。

## 8. 昵称记不住，或错误信息被记住

检查 `bot.memory.enabled` 和结构化记忆设置。第三方介绍默认只是候选，需要本人确认或足够独立来源支持；同一人重复不算多个来源，本人否认优先。

记忆以群 ID 和成员 ID 隔离，改群后不会自动沿用旧群记忆。`fresh_start` 跳过旧短期对话，不会清空已确认的长期记忆；只改 `member_memory.json` 不会更新已迁移的 SQLite 数据。

需要人工更正时先停止、备份，保持 `memory` 表与全文检索索引一致。不要上传整个记忆库求助；报告时提供经过处理的小范围示例即可。

## 9. 隐藏窗口、锁屏与服务器

支持窗口收起不等于支持注销、无桌面服务或所有远程桌面场景。微信客户端、登录会话与 Hook 必须保持运行。异常出现于锁屏或远程会话变化后，先在正常桌面会话里重新验证，不要假定只是 Python 后台方式的问题。

## 10. 图片识别失败或提示重新发图

- 先确认 `bot.vision.enabled=true`，使用支持图像输入的模型；示例 deepseek-flash 支持图像输入。
- 先发普通图片，再 @ 问“这张图写了什么”，或先提问后补图。不要用独立的动画表情消息、视频或合并转发测试普通图片识别。
- 默认只关联同一群、同一成员最近 120 秒内的图片；时间过久应重发。要看他人图片时明确引用并 @，不要只说“看看上面”。
- “图没加载出来”表示没有获取到有效像素，不是模型已经看过图。微信尚未缓存、账号不匹配、解密失败、文件损坏或尺寸超限都可能导致读取失败。可手动让微信加载图片后重新提问，或补发清晰截图；程序不会自动操作窗口下载原图。
- 日志出现“群图片已附入模型请求”说明已把实际像素放入请求；后续 API 报错应继续检查模型和网络。读取异常日志只记录异常类型，不应公开原图、密钥或整个账号目录。
- 首次提取图片密钥可能比后续识图慢。仍需区分本地读取耗时与模型回复耗时，不要以占位文字冒充识别结果。

## 11. 固定账号后无法启动或发送

`Hook account differs from the configured account` 表示当前 Hook 身份与本机 `bot.transport.account_username` 不一致。确认是不是正常切换了账号、填成了昵称而非 username，或另一个微信主实例占用了端口。

先停止机器人，确认目标账号及端口；只有确实要切换账号时才修改绑定值。不要为了继续运行随意清空绑定、关闭发送检查或使用另一个账号的数据库。绑定只控制机器人读取与发送，不代表其他微信实例没有加载 DLL。

## 提 Issue 前准备

提供系统、Python / 微信版本，前台还是隐藏运行，复现步骤、预期结果与实际结果，以及故障时段的必要日志。移除 API Key、代理密码、群 ID、成员 ID、聊天私密内容及用户目录路径。不要附账号数据库、密钥缓存或整个 logs 压缩包。
